Configuration

Everything is configured through environment variables (a .env file next to compose.yaml). The server validates its inputs at startup; the reviewer fingerprint below decides whether a head is considered “already reviewed”.

Server

Variable Default Purpose
APP_CLIENT_ID required GitHub App client ID (Iv1.…); an App ID also works.
APP_PRIVATE_KEY_BASE64 required* Base64-encoded App private key PEM. Generate with base64 < app.private-key.pem | tr -d '\n'. *Either this or APP_PRIVATE_KEY is required.
APP_PRIVATE_KEY — Alternative to base64: the PEM with \n escapes.
GITHUB_WEBHOOK_SECRET required High-entropy secret, identical to the one set on the GitHub App webhook. Generate with openssl rand -hex 32.
BOT_LOGIN hedgehog-pr-bot Your GitHub App’s bot account, e.g. my-reviewer for my-reviewer[bot]. Needed so the bot recognizes its own 👀, threads, and reviews. Set it when self-hosting with a differently named App.
PR_AUTHOR gregnazario Only review pull requests opened by this GitHub user. Set this to yourself.
PI_MODELS zai/glm-5.3:high Comma-separated reviewers in provider/model[:thinking] form. Thinking levels: off minimal low medium high xhigh max. Changing the list changes the review fingerprint, so open PRs get re-reviewed.
PR_AUTHORS PR_AUTHOR Comma-separated list of reviewed authors — maintainer mode for repos with outside contributors.
REVIEW_MEMORY_PATH unset File persisting /ignore fingerprints so muted findings stay muted. Unset disables the memory; mount a volume in read-only containers.
PI_TIMEOUT_MS 600000 Wall-clock cap for one model run; a hung run cannot block the queue.
NOTIFY_WEBHOOK unset POSTed with each review result: repository, PR, head, status, severity counts.
LOG_FORMAT text json emits one {time, level, message} object per log line.
DOMAIN unset Required only by the optional compose tls profile (Caddy).
PI_MODELS_LARGE unset Reviewers used for diffs above 500k characters — point this at a long-context or cheaper model. Participates in the review fingerprint.
REVIEW_VERIFY true A second model pass re-checks every Critical/High finding against the diff and confirms, downgrades, or drops it before anything is posted. Fails open: verification problems keep the original findings.
FILE_CONTEXT_BYTES 65536 Budget for embedding the complete contents of touched files in the prompt, so findings can reference the code a change calls into. 0 disables.
MAX_DIFF_CHARS 4000000 Diff cap sent to each model; larger diffs are truncated.
HOST / PORT 0.0.0.0 / 3000 Listen address inside the container.
BIND_ADDRESS / BIND_PORT 127.0.0.1 / 3000 Docker Compose host-side binding for your TLS proxy.
PI_VERSION 0.84.4 Pi version stamped into review footers and baked into the image.

Model credentials

Each configured provider needs its API key in the environment — Pi reads them directly. The default setup uses ZAI_API_KEY (Z.AI Coding Plan). Pi also supports providers such as Anthropic, OpenAI, OpenRouter, Gemini, xAI, and DeepSeek; add only the key variables for the models you configure, for example: 

PI_MODELS=zai/glm-5.3:high,anthropic/claude-sonnet-4-5:high
ZAI_API_KEY=…
ANTHROPIC_API_KEY=…

Hourly recovery scan

The optional GitHub Actions workflow re-reviews open PRs the server may have missed while down. It uses its own short-lived installation token, so it needs no server credentials:

Variable Default Purpose
GH_TOKEN required Provided by actions/create-github-app-token in the workflow.
MAX_REVIEWS_PER_RUN 5 Cap on reviews per hourly run.
PI_MODELS, PR_AUTHOR, BOT_LOGIN as above Keep these identical to the server so markers match.

GitHub App settings

Permission Access Used for
Contents read & write Reading pull-request diffs. Write exists only because GitHub gates the thread-resolution mutation behind it; hedgehog never pushes commits.
Issues read & write Reading /review comments.
Pull requests read & write Reviews, dismissals, thread replies, the 👀 reaction.
Checks write The Pi review check run.

Subscribe to the Pull request, Issue comment, and Pull request review comment webhook events — the last one powers /ignore. There is no separate “Reactions” permission in GitHub App settings.

Commands and labels

  • /review — comment this on your PR to force a re-review of the current head. Only reviewed authors may use it, and the bot reacts 👀 to the comment immediately so you know it landed.
  • /describe — comment this on your PR to get a drafted title and description from the diff, posted as a comment to copy into the PR.
  • /ignore — reply this under any hedgehog comment to mute that finding: the thread resolves, the reply gets 👍, and future passes drop matching findings (when REVIEW_MEMORY_PATH is set).
  • skip-review label — silence the bot on that PR: no queueing, no 👀, no check, and /review is ignored. Removing the label does not auto-trigger a review.

Per-repository configuration (.hedgehog.yml)

Each repository can tune its own reviews by committing a flat .hedgehog.yml: 

skip: false
ignore_paths: [dist, vendor]
min_severity: Medium
verify: false
instructions: |
  Flag client-only hooks; we use server components.
walkthrough: true
models: zai/glm-4.7:low
focus: [security, correctness]

skip silences the repository; ignore_paths drops findings under path prefixes; min_severity sets a posting floor; verify overrides the verification pass; instructions feeds maintainer guidance into every review; walkthrough adds a file-by-file summary to the review body; models overrides the server's model list (and the review fingerprint); focus narrows the review to a fixed set of categories — security, correctness, performance, reliability, maintainability, tests, accessibility — with a glossed, scoped prompt (out-of-focus Criticals still surface). Unknown keys and invalid values are ignored.

Observability

GET /healthz answers liveness with the queue depth; GET /metrics serves Prometheus text — webhook events by type, accepted and rejected counts, job results by status, ignore jobs, and queue depth — and GET /dashboard renders a live, auto-refreshing page with recent reviews and all counters (/dashboard.json for the same data as JSON; DASHBOARD_TOKEN gates both when set).

Review and check outcomes

Pass result GitHub review Check
No findings, no still-applying threads Approve — “No new findings.” ✅ success
Any Critical or High Request changes ⚠️ action_required
Medium/Low only Comment; own blocking reviews dismissed ℹ️ success
Pi or GitHub failure Nothing posted ❌ failure
