Your own AI code reviewer, wired straight into GitHub

hedgehog-pr-bot is an open-source pull-request reviewer. It listens to GitHub App webhooks for every pull request you open, sends the diff to Pi (a coding-agent harness), and posts the findings back as real GitHub review comments — on the exact lines, with severity, follow-up on its own previous threads, and a check run that reflects the outcome. No workflow file is needed in any reviewed repository.

How a review runs

  1. A webhook fires when one of your pull requests is opened, reopened, marked ready for review, or pushed to. You can also comment /review on a PR to force a re-run. The request is HMAC-verified and queued — one review runs at a time, and only the newest head per PR is kept.
  2. The worker re-checks the PR (still open, not a draft, right author, no skip-review label, not already reviewed for this head + model configuration), then adds a 👀 reaction and an in-progress Pi review check run.
  3. It fetches the diff plus its own still-open review threads, annotates line numbers into the diff, and runs a single Pi pass per configured model.
  4. Findings are posted as one GitHub review with inline comments. Fixed threads are resolved, still-valid ones get a “Still applies.” reply, and comments whose code moved are re-anchored. A clean pass approves; Critical/High findings request changes; Medium/Low only comment and clear the bot’s own blocking reviews.
  5. The check run finishes as ✅ clean, ℹ️ comments only, ⚠️ high/critical, or ❌ when the runner itself failed — findings never mark the build red.

What it looks at

  • Security vulnerabilities and unsafe trust boundaries
  • Correctness bugs and edge cases
  • Performance and scalability problems
  • Reliability, maintainability, and general code quality

Highlights

  • Account-wide by installation. Install the GitHub App on all your repositories (or a subset) — no per-repo setup.
  • Model-agnostic. The default is GLM-5.3 via a Z.AI Coding Plan, and PI_MODELS accepts any provider Pi supports, with per-model thinking levels. Multiple models review each revision independently.
  • Idempotent. A hidden marker per head SHA and model configuration means webhooks and the hourly recovery scan never double-post a review.
  • Hardened by default. Webhook signatures are verified constant-time; tokens, the App private key, and the webhook secret are stripped from the model’s environment; the container runs read-only, unprivileged, with no capabilities.
  • Boring stack. One Node.js process, zero runtime dependencies, strict TypeScript executed natively, Docker Compose for deployment.

Can I run it myself?

Yes — it is designed for one GitHub account (yours), not as a multi-tenant service. You create your own GitHub App, deploy the container anywhere with a public HTTPS endpoint, and point the App’s webhook at it. The self-hosting guide walks through the whole setup, and the configuration reference covers every environment variable.
